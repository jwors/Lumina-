# M0 · USB 连通性验证（PTP 握手与列取）

> Status: ready-for-agent
> 上游：`docs/SPEC-Lumina.md` §3.1、§7；词汇：`GLOSSARY.md`（Ingest / Master）

## Problem Statement

用户是尼康 Z30 徒步摄影者，市面上的导出 App 都没法让人信任地把原片从相机搬到手机。在写下整个 App 之前，必须先证明最关键、最不可回避的技术假设真实成立：**一部 Android 手机可以通过 USB OTG 线发现 Z30、与它建立 PTP 会话、列出存储卡里的照片清单**。这件事如果在 M0 验证失败，整个产品方向都要重新设计（退路仅剩 Wi-Fi PTP-IP）。

## Solution

一个最小可安装的 Android App（M0 探针，非最终产品）：插上 Z30 后，屏幕显示"发现相机 → 型号名 → 存储分区数 → 照片文件清单（文件名 + 大小）"。它只需要打通链路和列取，不做复制、不做图库、不做样式——M1 起的界面在它之上生长。

## User Stories

1. 作为徒步摄影者，我想插上 OTG 线后 App 自动告诉我"已发现相机"，这样我不需要懂任何协议就知道连接成功。
2. 作为徒步摄影者，我想在屏幕上看到相机型号（Z30），这样我确认连接的是我这台设备而不是别的 USB 设备。
3. 作为徒步摄影者，我想看到存储分区列表（卡1/机内内存），这样我知道原片都在哪。
4. 作为徒步摄影者，我想看到每张照片的文件名和体积，这样我能确认 NEF 和 JPEG 是成对的。
5. 作为徒步摄影者，我想在未授予 USB 权限时看到明确的引导提示，这样我知道去点系统弹窗而不是以为 App 坏了。
6. 作为徒步摄影者，我想在拔线后界面立即回到"未连接"状态，这样状态不会骗我。
7. 作为徒步摄影者，我想在相机休眠/超时断开时看到可理解的原因，而不是一个空白的报错。
8. 作为徒步摄影者，我想要 App 在再次插线时自动重连，这样我在营地反复插拔不用反复点按钮。
9. 作为徒步摄影者，我想清单按拍摄日期分组显示，这样我能一眼找到今天的拍摄。
10. 作为徒步摄影者，我想看到卡内照片总数与总体积的统计，这样我在 M1 导入前心里有数。
11. 作为 Arc agent（开发协作者），我可以在没有真机的情况下运行 PTP 协议解析的单测，这样协议层迭代不依赖每次都在相机旁。
12. 作为 Arc agent，我可以用一次录制的 PTP 响应字节流回放来测试解析器，这样边界情况（非标准厂商扩展）能沉淀成回归用例。
13. 作为未来的我（M1 开发），我希望"列取清单"返回的是结构化对象（句柄、文件名、大小、日期、父目录），这样复制功能可以直接复用同一会话。
14. 作为未来的我，我希望 Transport 层与协议层是物理隔离的两个模块，这样 M2 的 Wi-Fi PTP-IP 只需要替换传输层。
15. 作为自用工具的用户，我不需要这个探针 App 有任何样式追求，这样评审只看"信息对不对"而不是好不好看。
16. 作为被"垃圾 App"伤过的尼康用户，我想在 10 秒内从插线到看到清单，这样我不耐烦时不会放弃这个 App。
17. 作为 Android 用户，如果系统把我的相机识别成普通文件设备，我希望看到原生 MTP 列取或明确的失败记录，这样我们知道实际走了哪条协议路径。
18. 作为野外的用户，App 全程不联网也不请求任何网络权限，这样我可以放心它不会偷偷传我的照片。（本里程碑的隐私底线）
19. 作为一个谨慎的人，我想在屏幕上看到 PTP 会话日志（最近几行），这样 troubleshooting 时我能拍照发给 Arc agent 定位。
20. 作为 Arc agent，我希望探针把设备/协议异常写进本地日志文件，这样真机现场的问题不需要复现也能回溯。

## Implementation Decisions

*（按 `docs/adr/0001`：Kotlin 原生；以下不含具体文件路径）*

1. **模块划分**：三个纵向切片——`transport`（USB OTG 字节传输）、`ptp`（协议编解码与会话）、`probe`（最小 Compose 界面）。`transport` 与 `ptp` 之间只有 Transport 接口一处耦合。
2. **唯一新缝隙（经 grilling 共识推演，M0 spec 评审时确认）**：`Transport` 接口，抽象为"打开 → 读块 → 写块 → 关闭"。USB 实现薄到只剩 UsbManager/UsbDeviceConnection 的调用；协议层完全 ignorant of Android USB API。
3. **PTP 实现**：不引入 gphoto2/JMTP 等重型绑定，直接实现 PTP/IP-free 的 USB 纯 PTP 容器（OperatedRequest 0x1001 OpenSession、0x1007 GetDevicePropValue 型号查询、0x1008 GetStorageIDs、0x1007/0x1009 GetObjectInfo 遍历）。理由：这个子集不到 200 行，而完整库的 JNI 绑定是 M0 最大的额外风险。
4. **MTP 回退**：Z30 正常枚举为 PTP（影像设备 class）。若手机上被识别为 MTP 类，用 android-framework 的 MtpManager 兜底列出清单，同时在日志里记录走了哪条路径（对应 user story 17）。
5. **日期分组**：列取时用 object 的 Capture Date 属性，不递归全存储；JPEG+NEF 不做配对（M1 的事）。
6. **无网络**：探针 AndroidManifest 不声明任何 INTERNET 权限，作为 M0 的隐私测试断言之一。
7. **日志**：环形缓冲的会话日志（最近 N 行）常驻显示 + 完整日志落应用私有目录。

## Testing Decisions

- **好测试的标准**：只测协议层外部行为（给它什么样的字节序列，它应返回什么样的对象/调用什么样的 Transport 请求），不测内部函数拆分。
- **测哪里**：全部火力在 `ptp` 模块的 JVM 单测——伪造 Transport（给定响应字节流，断言发出的请求字节）覆盖：OpenSession 成功/失败、设备型号解析、存储枚举、对象清单解析（含中长文件名、NEF 扩展名、大文件体积、父目录遍历终止）。
- **回归沉淀**：真机调试时的实际响应字节可一键 dump，作为新用例回放进测试资源（user story 12）。
- **UI 不设测试**：探针界面是 throwaway，行为由"真机 10 秒插线看到清单"的人肉验收承担。
- **先例**：仓库尚无测试（M0 是第一刀），M1 起所有协议/文件名/日期处理都沿用此 Transport-伪化模式。

## Out of Scope

- 任何文件复制/Ingest 动作（M1）
- Exif/日期强解析、JPEG-NEF 配对（M1）
- 图库浏览界面、样式皮肤、Grain 视觉方向的应用（M1+）
- Wi-Fi PTP-IP（M4）；蓝牙（永久拒绝，ADR-0003）
- 进程常驻、后台服务、开机自启
- 性能调优（列表用简单遍历，速度够 M0 验收即可）

## Further Notes

- 真机验收标准（10 秒规则）：插线 → 系统弹 USB 权限 → 授权 → 屏幕出现 Z30 与卡内照片前 100 条（文件名+大小）。
- 若 Z30 需要相机端设置为 "MTP/PTP" 模式，把这一步写进屏幕引导文案。
- 本探针里程碑结束后，`probe` 界面可以被 M1 的完整 UI 直接替换，transport/ptp 两模块原样保留生长。
